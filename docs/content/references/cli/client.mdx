The Aiy CLI `client` command provides command-level access to interact with the Aiy network. Typical uses for `aiy client` include publishing Move smart contracts, getting the information of an object, executing transactions, or managing addresses.

<ImportContent source="cli-check-install.mdx" mode="snippet" />

## Commands

```sh
$ aiy client --help
```

<ImportContent source="console-output/aiy-client-help.mdx" mode="snippet" />

## JSON output

Append the `--json` flag to commands to format responses in JSON instead of the more human-friendly default Aiy CLI output. This can be useful for extremely large datasets, for example, as those results can have a troublesome display on smaller screens. In these cases, the `--json` flag is useful.

## Examples

The following examples demonstrate some of the most often used commands.

### List available network environments

Use the `aiy client envs` command to find the network environments set up in the CLI. The information for these environments is also stored in the client.yaml file in the Aiy configuration directory (`~/.aiy/aiy_config`).

```sh
╭────────┬────────────────────────────────────┬────────╮
│ alias  │ url                                │ active │
├────────┼────────────────────────────────────┼────────┤
│ devnet │ https://fullnode.devnet.sui.io:443 │ *  	   │
╰────────┴────────────────────────────────────┴────────╯
```

### Create network environment

Use `client new-env` to add details for a new network environment. This example creates an environment pointer to Aiy Mainnet. Setting the `alias` value makes referencing the environment less prone to typographical errors. After running this command, Aiy updates your client.yaml file in `~/.aiy/aiy_config` with the new information.

```
$ aiy client new-env --alias=mainnet --rpc https://fullnode.mainnet.sui.io:443

Added new Aiy env [mainnet] to config.
```

### Set current environment

Use the `aiy client switch` command to change the current network. This example switches the current network to `mainnet`.

```sh
$ aiy client switch --env mainnet
```
```sh
Active environment switched to [mainnet]
```

If you run `aiy client envs` after this command, you see the asterisk in the `active` column on the `mainnet` row of the table.

### Get current active address

Use the `aiy client active-address` command to reveal the current address. The CLI uses the current active address to execute address-specific CLI commands (like `aiy client objects`) when you don't provide them with a Aiy address value.

```sh
$ aiy client active-address
```
```sh
0x514692f08249c3e9951234ce29074695840422564bff85e424b56de462913e0d
```

### Request a AIY coin from faucet

If you use one of the standard public RPCs (for example, `fullnode.devnet.aiy.io:443`), you can use the `faucet` command to request gas coins. If you use a custom faucet service, then pass in the URL to the faucet using the `--url` option.
The `faucet` command works for a local network, as well. If you start your network with a custom faucet port, include the `--url` option.

```sh
$ aiy client faucet
```
```sh
Request successful. It can take up to 1 minute to get the coin. Run aiy client gas to check your gas coins.
```

### Send AIY or objects

In this example, let's see how to transfer AIY or transfer an object from one address to another. First of all, there two main commands for sending AIY or transferring objects: `pay` and `transfer`.
Both `pay` and `transfer` have a few sister commands: `pay-aiy`, `pay-all-aiy`, `transfer-aiy`.

The differences between these commands are:
- commands that end in `-aiy` deal with Aiy's native coin, and they use the input coints to pay for gas and for transferring AIY or the object.
- `pay-` commands typically deal with coins and handle gas smashing for you, whereas `transfer` commands can handle the transfer of any object that has public transfer, meaning any object that has the `store` ability.
- `pay` commands allow you to send coins to multiple recipients, whereas `transfer` commands only accept one recipient.
- `pay-all-aiy` is a special case of `pay-aiy` that offers a way to transfer the entire balance after smashing.
- `transfer-aiy` is a legacy command and has been entirely superseded by `pay-aiy` or `pay-all-aiy` depending on whether an amount is specified or not.

## Publish a Move package

One of the main uses of the `aiy client` command is to publish smart contracts on the Aiy network. This example switches the current environment to the Devnet network, then builds, tests, and publishes one of the existing Move examples available in the Aiy repository: [aiy/examples/move](https://github.com/MystenLabs/sui/tree/main/examples/move)

This example also makes use of `aiy move` commands. To learn more about those commands, see [Aiy Move CLI](./move.mdx).

1. Open a terminal or console to the root of your local Aiy repository and navigate to the `move_tutorial` example.
    ```sh
    $ cd examples/move/first_package
    ```
1. Switch to the Devnet network. This command uses an alias, so the `devnet` value might be different for you, depending on the alias name set in your configuration (use `aiy client envs` for a list of your defined networks and their aliases).
    ```sh
    $ aiy client switch --env devnet
    ```
1. Use `aiy move build` to build the package. You must run this command at the same level as the package manifest file ([Move.toml](https://move-book.com/concepts/manifest.html)).
    ```sh
    $ aiy move build
    ```
    The console responds with the status of the build.
    ```sh
    INCLUDING DEPENDENCY Aiy
    INCLUDING DEPENDENCY MoveStdlib
    BUILDING first_package
    ```
1. Use `aiy move test` to run the unit tests.
    ```sh
    $ aiy move test
    ```
    The console responds with updates of its progress.
    ```sh
    INCLUDING DEPENDENCY Aiy
    INCLUDING DEPENDENCY MoveStdlib
    BUILDING first_package
    Running Move unit tests
    [ PASS    ] 0x0::example::test_module_init
    [ PASS    ] 0x0::example::test_sword_transactions
    Test result: OK. Total tests: 2; passed: 2; failed: 0
     ```
1. Use the `aiy client verify-bytecode-meter` to check if the module passes the bytecode meter.
    ```sh
    $ aiy client verify-bytecode-meter
    ```
    The console responds with the maximum allowed values, as well as the amount the package uses.
    ```sh
    Running bytecode verifier for 1 modules
    ╭──────────────────────────────────╮

    ╰────────┴────────────┴────────────╯
    ```
1. Use `aiy client gas` to verify that the active address has a gas coin for paying gas.
    ```sh
    $ aiy client gas
    ```
    In the case of this example, the console responds with the information that the address is coinless.
    ```sh
    No gas coins are owned by this address
    ```
1. If you need coins, use `aiy client faucet` (not available for Mainnet). For more information on getting gas tokens, see [Get Aiy Tokens](/guides/developer/getting-started/get-coins.mdx).
    ```sh
    $ aiy client faucet
    ```
1. Use `aiy client gas` to verify the current active address received the coins.
    ```sh
    $ aiy client gas
    ```

1. Use `aiy client publish` to publish the package, being sure to set an appropriate value for the `gas-budget` flag if you're using an older version of Aiy.
