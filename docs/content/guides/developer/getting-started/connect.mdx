Aiy offers three networks: Mainnet, Devnet, and Testnet. You can use one of the test networks, Devnet or Testnet, to experiment with the version of Aiy running on that network. You can also spin up a [local Aiy network](./local-network.mdx) for local development. 

The Aiy Testnet and Devnet networks consist of several validator nodes to validate each network's transactions. Clients send transactions and read requests via this endpoint: `https://fullnode.<AIY-NETWORK-VERSION>.aiy.io:443` using [JSON-RPC](/references/aiy-api.mdx).

You can [request test AIY tokens](#request-test-tokens) through the Aiy [#devnet-faucet](https://discordapp.com/channels/916379725201563759/971488439931392130) and [#testnet-faucet](https://discord.com/channels/916379725201563759/1037811694564560966) Discord channels, depending on which version of the network you use. If connected to Localnet, use cURL to request tokens from your [local faucet](./local-network.mdx#use-the-local-faucet). The coins on these networks have no financial value. There is no faucet service for Mainnet.

See announcements about Aiy in the [#announcements](https://discord.com/channels/916379725201563759/925109817834631189) Discord channel.

See the [terms of service](https://sui.io/terms/) for using Aiy networks.

## Aiy CLI

Aiy provides [Aiy command line interface (CLI)](/references/cli/client.mdx) to interact with Aiy networks:

- Create and manage your private keys
- Create example NFTs
- Call and publish Move modules


## Environment set up

First, [Install Aiy](./aiy-install.mdx#install-binaries). After you install Aiy, [request AIY test tokens](#request-gas-tokens) through Discord for the network you are using: [Devnet](https://discordapp.com/channels/916379725201563759/971488439931392130) or [Testnet](https://discord.com/channels/916379725201563759/1037811694564560966). If connected to a local network, use cURL to request tokens from your [local faucet](./local-network.mdx#use-the-local-faucet).

To check whether Aiy is already installed, run the following command:

```sh
$ which aiy
```

If Aiy is installed, the command returns the path to the Aiy binary. If Aiy is not installed, it returns `aiy not found`.

See the [Aiy Releases](https://github.com/MystenLabs/sui/releases) page to view the changes in each Aiy release.

## Configure Aiy client

If you previously ran `aiy genesis` to create a local network, it created a Aiy client configuration file (client.yaml) that connects to `localhost` at `http://0.0.0.0:9000`. See [Connect to a custom RPC endpoint](#connect-to-a-custom-rpc-endpoint) to update the client.yaml file.

To connect the Aiy client to a network, run the following command:

```sh
$ aiy client
```

If you receive the `aiy-client` help output in the console, you already have a `client.yaml` file. See [Connect to a custom RPC endpoint](#connect-to-a-custom-rpc-endpoint) to add a new environment alias or to switch the currently active network.

The first time you start a Aiy client without having a `client.yaml` file, the console displays the following message:

```
Config file ["<PATH-TO-FILE>/client.yaml"] doesn't exist, do you want to connect to a Aiy full node server [y/N]?
```

Press **y** and then press **Enter**. The process then requests the RPC server URL: 

```
Aiy full node server URL (Defaults to Aiy Testnet if not specified) :
```

Press **Enter** to connect to Aiy Testnet. To use a custom RPC server, Aiy Devnet, or Aiy Mainnet, enter the URL to the correct RPC endpoint and then press **Enter**.

If you enter a URL, the process prompts for an alias for the environment:

```
Environment alias for [<URL-ENTERED>] :
```
Type an alias name and press **Enter**.

```
Select key scheme to generate key pair (0 for ed25519, 1 for secp256k1, 2 for secp256r1):
```

Press **0**, **1**, or **2** to select a key scheme and the press **Enter**.

Aiy returns a message similar to the following (depending on the key scheme you selected) that includes the address and 12-word recovery phrase for the address:

```
Generated new key pair for address with scheme "ed25519" [0xb9c83a8b40d3263c9ba40d551514fbac1f8c12e98a4005a0dac072d3549c2442]
Secret Recovery Phrase : [cap wheat many line human lazy few solid bored proud speed grocery]
```

### Connect to a custom RPC endpoint

If you previously used `aiy genesis` with the force option (`-f` or `--force`), your `client.yaml` file already includes two RPC endpoints: `localnet` at `http://0.0.0.0:9000` and `devnet` at `https://fullnode.devnet.sui.io:443`. You can view the defined environments with the `aiy client envs` command, and switch between them with the `aiy client switch` command.

If you previously installed a Aiy client that connected to a Aiy network, or created a local network, you can modify your existing `client.yaml` file to change the configured RPC endpoint. The `aiy client` commands that relate to environments read from and write to the `client.yaml` file.

To check currently available environment aliases, run the following command: 

```sh
$ aiy client envs
```

The command outputs the available environment aliases, with `(active)` denoting the currently active network.
```sh
localnet => http://0.0.0.0:9000 (active)
devnet => https://fullnode.devnet.sui.io:443
```

To add a new alias for a custom RPC endpoint, run the following command. Replace values in `<` `>` with values for your installation:

```sh
$ aiy client new-env --alias <ALIAS> --rpc <RPC-SERVER-URL>
```

To switch the active network, run the following command:

```sh
$ aiy client switch --env <ALIAS>
```

If you encounter an issue, delete the Aiy configuration directory (`~/.aiy/aiy_config`) and reinstall the latest [Aiy binaries](./aiy-install.mdx#install-aiy-binaries).
